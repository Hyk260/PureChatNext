# PureChat 支持哪些文件：PDF、Office、文本与图片

PureChatNext 可以在聊天中读取常见文本、PDF 和 Office 文档，并把提取出的文本交给所选模型回答。聊天输入当前最多添加 8 个附件，每个附件不超过 10 MB；图片走模型视觉能力，不能把普通 OCR 当作所有模型都具备的功能。

## 支持范围

聊天附件选择器接受以下类型：

| 类型 | 当前支持的扩展名 / 条件 | 处理方式 |
| --- | --- | --- |
| 文本和表格 | `.txt`、`.md`、`.csv` | 提取文本后随当前消息发送给模型。 |
| PDF | `.pdf` | 提取 PDF 中可读取的文本；扫描件如果没有文本层，可能没有可供模型读取的内容。 |
| Word | `.doc`、`.docx` | 提取文档文字；复杂排版不保证和原文件视觉效果一致。 |
| Excel | `.xls`、`.xlsx` | 提取工作表中的单元格内容；表格样式和布局不会原样传给模型。 |
| PowerPoint | `.pptx` | 提取幻灯片文本；不保留完整版式与动画信息。 |
| 图片 | 浏览器可选的 `image/*` | 作为图像内容发送给视觉模型；当前模型不支持视觉时会返回错误。 |

文件解析器还识别代码、配置和标记文本扩展名，但它们不都出现在聊天文件选择器的显式扩展名列表中。不要把任意二进制文件、压缩包或可执行文件当作可解析附件。

## 上传限制与模型输入

- 每条消息最多 8 个附件，每个文件最多 10 MB。
- 文档解析后的文本单文件最多取前 40,000 个字符作为本轮模型输入；超出的部分不会进入这次请求。
- 图片不会使用 Office/PDF 文本解析器。必须选择支持视觉输入的模型，否则请求会被拒绝。
- 模型只会看到提取文本或图像内容，不会自动理解 PDF 页面的扫描图、Excel 格式、幻灯片动画或原始排版。
- 模型调用可能产生费用，费用取决于所选服务商、模型及输入长度。

在自托管环境使用文件与附件上传时，按 [Docker 自托管](../platform/docker.md) 配置 S3 兼容对象存储。文件处理不等于知识库索引：每次提问都应把相关文件附在对话中，不要假设上传一次后会自动建立永久向量索引。

## 使用文件提问

1. 打开一个聊天会话，使用附件按钮添加受支持的文件。
2. 文件名出现在输入区后，提出一个具体问题，例如指定 PDF 的章节、Excel 的工作表或 Word 的段落主题。
3. 如果附件是图片，检查当前模型是否支持视觉输入。
4. 若回答缺少信息，先确认文件可选中文本、文件未超过限制，再把问题缩小到具体页、表或段落。

## 常见问题

**扫描 PDF 没有回答内容怎么办？**

当前 PDF 解析走文本提取路径，不承诺扫描件 OCR。可先把文件转换为含文本层的 PDF，或把需要分析的页面导出为图片并选择支持视觉输入的模型。

**为什么图片附件提示模型不支持？**

图片理解依赖所选 Provider/模型的视觉能力。切换到支持图像输入的模型后再发送。

**为什么长文档只回答前面一部分？**

聊天请求限制每个文档进入模型的提取文本长度。将问题聚焦到特定章节，或拆分为更小的文件后重试。

**自托管部署还要准备什么？**

生产附件存储需要 S3 兼容对象存储配置。数据库、模型 Provider 和对象存储的准备项见 [Docker 自托管](../platform/docker.md) 与[环境变量配置](../configuration/environment.md)。
