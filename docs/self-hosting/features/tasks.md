# 自动化任务与定时任务

任务页面支持创建云端定时任务：选择助理、模型、优先级、执行说明、运行频率与通知渠道。普通任务列表暂时保留为后续能力入口。定时任务在服务端独立运行，不依赖用户浏览器或当前聊天窗口保持打开。

## 部署要求

- 使用持久运行的 Node.js 自部署实例、PostgreSQL 和数据库迁移 `0040_wooden_smiling_tiger.sql`。
- 生产环境设置 `TASK_SCHEDULER_ENABLED=1` 并重启服务。Docker Compose 自托管配置默认启用；普通 `pnpm dev` 默认关闭，开发时可在启动 Next 前设置该变量。
- 调度器在 Next `instrumentation` 启动，与 `CHANNEL_GATEWAY_ENABLED` 相互独立。多实例可同时运行，数据库租约只允许持有者调度；到期任务、运行锁和重启恢复状态都保存在数据库中。
- Vercel 明确不启动任务调度器。使用 Vercel 的站点可访问任务页面，但要在自部署的持久服务中创建并执行任务。

任务使用所选助理的系统指令与用户已保存的服务商凭证；助理若配置了模型，默认使用该模型，否则沿用工作台当前模型。云端执行支持文本生成、已配置的网页搜索与天气工具，不会调用本地桌面能力。每次执行使用独立上下文，完整结果与运行诊断保存在任务记录中。

## 频率、时区与状态

默认时区为 `Asia/Shanghai`，可选择每日、每小时或每周多日运行。每小时按所选分钟运行，每日和每周按所选时分运行；调度器按所选 IANA 时区计算夏令时。

一次执行成功后任务进入「待审阅」，失败在最终重试后保留失败运行记录并通知用户。定时安排继续生效，不会因为「待审阅」而暂停下一次执行。「已完成」和「已取消」会关闭定时安排并终止未完成运行；要暂时停用但保留任务，可关闭独立的「启用定时」开关。

服务重启或停机导致错过的执行仅补跑最近一次：最近一次到期不超过 15 分钟则补跑，较早的错过周期合并为跳过记录。任务按优先级排队；同一账号同时只运行一个任务。每次最多执行 5 分钟，临时失败最多尝试三次。

## QQ 与微信通知

通知发送给任务所属账号的本人私聊。通知包含任务状态、结果摘要（最多 1000 个字符）和应用内运行详情链接；完整结果留在任务详情中。渠道可多选，任务成功和最终失败都会创建独立通知投递记录。网络结果不确定的发送会标记为「结果待核实」，不会自动重复推送；明确可重试错误与用户手动重发不会重新执行模型任务。

### QQ

QQ 定时通知使用 C2C 主动消息接口发送，不携带 `msg_id` / `event_id`，因此不受 60 分钟被动回复窗口限制。它仍受 QQ 开放平台的主动消息权限、用户关系和频率限制约束；接口拒绝时会在运行记录中显示原因。请查看腾讯的[消息发送方式说明](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/overview.html)和[C2C 单聊发送接口](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_users_user_openid_messages.post.html)。

在 QQ 高级设置中填写本人 `user_openid` 后才能推送。该标识不是 QQ 号，也不是 `tiny_id`；可先与机器人交互，再从 QQ 入站事件中取得。若用户关系、机器人权限或平台频率限制不满足，任务结果仍可在任务详情中查看，并可在解决平台问题后手动重试投递。

### 微信

微信 iLink 发送需要同一账号最近入站消息保存的 `context_token`。如果令牌缺失或平台已不接受，投递会标记为需要操作；用户重新向机器人发消息后再重试。界面显示「平台已接受」只表示发送接口接受请求，实际可见性仍取决于微信会话与平台状态。

## 检查运行状态

打开任务页查看调度器健康状态、任务下次执行时间、运行历史和每个通知渠道的投递状态。若调度器异常，先确认 `TASK_SCHEDULER_ENABLED=1`、数据库连接与迁移状态，再查看 Next 服务日志。QQ 推送失败时检查本人 `user_openid`、机器人 C2C 主动消息权限和用户关系；微信推送失败时检查绑定状态，并在需要时重新发送一条消息以刷新会话凭据。
